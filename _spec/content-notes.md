## 機能の保護

`app.js` のドットスフィアは212–319行の自己完結した IIFE です。`[data-sphere="on"]`、`.hero` / `.thanks-hero`、`[data-scene="dark"]` を読み、body 直下へ `.sphere-canvas` を作ります。描画位置は viewport 基準で、CSS は固定配置と pointer-events:none を維持する必要があります。元ブロックの SHA-256 は JSON に保存しました。位置変更以外で描画・回転ロジックを変更する必要はありません。

問い合わせ送信の共通JSは884行から末尾の `onScroll()` 直前です。`.ct-form`、`.ct-submit`、`_next`、添付フィールドと action に依存します。ブロックの SHA-256 を保存しました。apply は Web3Forms のフォームを持ち、ページ内の inline JS を使います。汎用4ページの全 inline script と全 hidden input のハッシュを保存しました。フォーム以外でも inline script 全体を保持すれば、UIだけを変更できます。

通常ページの既存 `app.js` は header / progressBar を null チェックなしで読むため、JSを整理する場合は保護ブロックだけを独立させる方が簡潔です。スクロールの過剰な既存演出、カーソルオーブ、ambient dots、worldmap、動画の制御を新構成へ持ち込む必要はありません。

robots.txt は `User-agent: *` / `Disallow: /`。既存404だけ meta robots が `noindex` なので、仕様の `noindex,nofollow` へ統一します。en ディレクトリを削除するとき、ヘッダー言語切替と英語 hreflang 参照も取り除きます。
